# BODYFORGE · Кузница тела · мобильный MVP v0.3.0

BODYFORGE — мобильная фитнес-RPG в стиле объёмной кузницы. Создай человека-бойца с выбранным телосложением, выполни **20 приседаний перед вертикальной камерой 9:16**, заработай **120 XP + 35 монет**, улучши мышцы и переодень 3D-персонажа. Также работают локальные ежедневные задания, 5 этажей башни с ботами и соревнование с собственной «тенью»; сетевой PvP ещё не подключён.

## Локальный запуск

Требуется Node.js 22+ и npm.

```bash
npm ci
npm run dev
```

Откройте адрес Vite (обычно **http://localhost:5173**). Разрешите использование камеры.

## Проверка

```bash
npm test -- --maxWorkers=1 --no-file-parallelism
npm run build
```

### Сквозные мобильные тесты (Windows + Google Chrome)

В одном терминале запустите `npm run dev`. В другом выполните:

```bash
npm run qa:privacy
npm run qa:mobile
npm run qa:tower20
npm run qa:resilience
```

`qa:mobile` проверяет создание бойца, переключение пяти мобильных экранов, WebGL-модель, награды, прокачку, покупку одежды, сохранение и работу камеры. `qa:tower20` подаёт **синтетические точки суставов** и проверяет 20 повторений, автофиниш, награды башни, запись «тени» и ежедневный квест. Тесты работают в **отдельном временном профиле Chrome**, не используют пользовательский прогресс и удаляют профиль после завершения. Эти тесты **не подтверждают точность на реальном человеке**. Используется локальный Chrome по пути `C:\Program Files\Google\Chrome\Application\chrome.exe`.

Для камеры нужна безопасная среда: **HTTPS или localhost**. Открыть локальный HTTP-сервер по IP с другого телефона недостаточно — браузер может заблокировать камеру. Для телефона используйте HTTPS-хостинг либо доверенный HTTPS-туннель.

## Игровой цикл на телефоне

1. На первом экране выберите **стройное или крепкое телосложение**, задайте имя бойцу. Уже заработанные до обновления XP и монеты остаются в браузере.
2. Во вкладке **Камера** выполните 20 приседаний. Счётчик и таймер автоматически завершат попытку; получите XP и монеты.
3. Во вкладке **Герой** улучшайте руки, пресс, ноги и спину (до уровня 5 каждую). Изменения отображаются на вращаемой 3D-модели. Покупайте и надевайте форму за монеты.
4. На главной странице забирайте ежедневную награду и выполняйте квест за 20 приседаний.
5. Во вкладке **Башня** побеждайте виртуальных соперников по времени. После первого завершённого испытания откроется бой с собственной «тенью» — сохранёнными временами каждого повторения.
6. Вкладка **Онлайн** обозначает будущие аккаунты, PvP и рейтинг. Пока все бои с ботами локальные, а сетевое взаимодействие отсутствует.

На мобильном экране используется пять настоящих вкладок: **Горн / Камера / Герой / Башня / Онлайн**. Для 3D нужен WebGL; на неподдерживаемых телефонах автоматически показывается облегчённый SVG. При запуске камеры невидимые 3D-модели отключаются для экономии ресурсов.

## Как выполнять испытание

1. Поставьте телефон **вертикально**, устойчиво, сбоку от себя. В кадре 9:16 должны целиком помещаться таз, колени и стопы.
2. Нажмите «Начать закалку» и разрешите доступ к камере.
3. Встаньте боком и выпрямите ноги — это калибрует счётчик и запускает секундомер.
4. Сделайте 20 полных приседаний. Для зачёта требуется достаточная глубина и полное выпрямление ног. При включённом звуке каждый засчитанный повтор сопровождается коротким сигналом.
5. После 20-го повтора счётчик сам завершит занятие, остановит таймер, отключит камеру и начислит награду. Сигнал последнего повтора двойной.

## Камера в портретном формате

- Запрос браузеру: предпочтительный поток **720 × 1280**, `aspectRatio: 9 / 16`, первоначально фронтальная камера (если доступна).
- Окно на экране всегда вертикальное **9:16** и на смартфоне, и на компьютере. Видео и скелет используют одинаковое `object-fit: cover`.
- Браузер может **не выполнить пожелания** к разрешению: горизонтальная веб-камера отдаст широкое видео, центральная часть будет показана в портретном окне. При этом приложение показывает предупреждение. Чтобы не обрезать человека, встаньте по центру и подберите расстояние.
- На узком экране активное окно прокручивается в центральную область для видимости счётчика.

### Управление объективами и масштабом

Надпись обычной камеры «Wide-Angle» не означает объектив 0.5×. Приложение больше не приравнивает эти названия: кнопка широкого объектива и ползунок отражают только возможности, сообщённые браузером. Наличие зума меньше 1× само по себе не доказывает оптическое переключение объектива.

- Во вкладке **«Камера»** доступны кнопки **«Селфи»**, **«Основная 1×»**, **«Широкая 0.5×»**, «Обновить» и список обнаруженных камер. Выбор работает до и во время тренировки; для новых устройств сначала требуется разрешение на камеру.
- Кнопка **«Широкая 0.5×»** доступна, **только если браузер сообщил об отдельном сверхширокоугольном устройстве** либо активный видеотрек поддерживает масштаб меньше 1×. Если объектив есть в телефоне, но не открыт для WebRTC, принудительно включить его с сайта нельзя. Если названия непонятны, попробуйте вручную выбрать одну из «Обнаруженных камер».
- Если браузер поддерживает масштаб, появится ползунок с **реальным диапазоном `MediaStreamTrack.getCapabilities().zoom`**. Это изменение видеотрека, не цифровое растягивание предпросмотра.
- При смене камеры приложение отключает предыдущий поток, запрашивает новый и **перекалибрует стойку без потери завершённых повторений**. Начатый, но не завершённый присед не учитывается; **таймер продолжает идти**. Если выбранная камера недоступна, приложение пытается восстановить прежнюю; при невозможности восстановления завершает попытку без награды.
- Независимо от объектива рамка остаётся **вертикальной 9:16**. Настройка **«Показать весь кадр»** меняет отображение видеопотока и скелета с обрезки краёв на `object-fit: contain`, сохраняя всю широкую картинку внутри портретной рамки. При этом вокруг горизонтального потока могут появиться пустые полосы; человек может стать мельче. На сверхшироком объективе держите тело ближе к центру изображения: по краям перспектива искажена.

## Архитектура

- React + TypeScript + Vite: UI.
- MediaPipe Pose Landmarker: 33 точки тела в браузере.
- `src/lib/camera.ts`: выбор `facingMode` / `deviceId`, распознавание заявленного широкого объектива, диапазона zoom, портретные ограничения и проверка ориентации.
- `src/components/CameraControls.tsx`: управление доступными камерами, 0.5× и масштабом на мобильном экране.
- `src/forge.css`: кузнечный стиль (уголь, сталь, медь и жар), мобильная портретная компоновка.
- `src/lib/squatCounter.ts`: счётчик калибрует **измеренную прямую стойку для каждого пользователя**, затем определяет заметный сгиб ноги и возвращение в стойку. Стабилизирует выбор левой/правой ноги, а при длительной потере отслеживания требует повторной калибровки, сохраняя предыдущие повторы. Тестируемый без камеры.
- `src/lib/progression.ts`: XP, монеты, уровни, результаты, времена отдельных повторений и совместимое локальное сохранение.
- `src/lib/game.ts`: персонаж, выбор телосложения, усиление мышц, магазин одежды, ежедневные квесты, башня и «тень».
- `src/components/Avatar3D.tsx`: настоящие WebGL-меши через Three.js — объёмное тело, свет, морфология мышц и материалы одежды.
- `src/components/GameAvatar.tsx`: ленивое подключение WebGL только на видимых экранах и облегчённая SVG-замена.
- `src/components/ForgeWorld.tsx`: игровые мобильные экраны создания бойца, прокачки, заданий, башни и статуса онлайна.
- `src/world.css`: объёмные металлические панели, мобильные вкладки и элементы игрового интерфейса.
- `src/components/Avatar.tsx`: лёгкая резервная SVG-модель для устройств без WebGL.
- `src/App.tsx`: работа с камерой и её отключением, загрузкой модели, рисованием скелета, таймером, звуковыми сигналами и автоматическим завершением.

## Надёжность сохранений и камеры

После аудита 19.10.2026:

- **Повреждённое сохранение:** отдельный экран предлагает восстановить проверенную резервную копию. Нового бойца нельзя создать поверх повреждённых данных автоматически. Новый пустой профиль требует второго подтверждения; повреждённый исходник предварительно сохраняется отдельно внутри этого же браузера.
- **Ошибка записи или заполненная память:** приложение больше не делает вид, что прогресс сохранён. Доступны повторная запись и локальный экспорт JSON текущей страницы. При конфликте с другой вкладкой предлагается явно открыть её актуальное сохранение. Это оптимистическая проверка версий, **не транзакционная защита одновременной записи и не онлайн-античит**.
- **Резервная копия:** повторный запуск и одинаковая запись не подменяют предыдущий полезный снимок идентичным текущему.
- **Статистика:** новые накопительные счётчики тренировок, повторений и лучшего времени не зависят от ограничения истории в 60 записей. Ранее уже удалённые историей тренировки восстановить из отсутствующих данных невозможно: старый профиль начинает счёт с доступной истории.
- **Повторное событие финиша:** одна сессия имеет один идентификатор, повторная обработка не удваивает XP/награды. Это защита локального текущего результата, не серверное доказательство честности.
- **Камера:** при зависшем кадре устаревший угол и скелет очищаются. Таймер продолжает идти; завершённые повторы сохраняются. При уходе приложения в фон попытка прекращается без награды.
- **Долгое ожидание:** ограничено время открытия камеры, видеоплеера, загрузки модели и применения зума. Поздно полученный после тайм-аута/отмены поток закрывается. Во время изменения масштаба распознавание приостановлено.
- **3D:** неудачная загрузка отдельного 3D-модуля не обрушает всё приложение; показывается облегчённый персонаж с предупреждением.
- **Ежедневные награды:** доступность обновляется после смены даты и возвращения во вкладку без перезагрузки страницы.

`npm run qa:resilience` проверяет отказоустойчивость интерфейса в изолированном временном профиле Chrome: повреждение/восстановление, отказ хранилища и квоту, конфликт вкладок, переход даты, отказ камеры, зависание кадров, отмену отложенного потока, гонку изменения зума, pagehide, сбой модели и отсутствие 3D-модуля. Всё это **искусственные контролируемые сценарии**, не запись движений человека.

Подробная матрица покрытия и оставшихся рисков: `docs/audits/2026-10-19-reliability.md`.

## Приватность и ограничения MVP

- Видео **не загружается на сервер и не сохраняется**. Детекция проходит на устройстве.
- Модель позы загружается из Google Cloud Storage, файлы WebAssembly — из CDN jsDelivr. При первом запуске нужен интернет. Не добавляйте в проект токены и `.env`.
- Прогресс сохраняется **только в localStorage этого браузера**. Очистка данных браузера удалит его.
- Это прототип счётчика, не медицинская проверка техники. Угол колена зависит от ракурса, света, одежды и видимости суставов. Возможны пропуски/ложные срабатывания; при обрезке боков широкого видео центрируйте человека. Скоростной PvP пока не поддерживается.
- Магазин одежды, персонаж, башня, локальные боты и «тень» работают **только в браузере**. Учётные записи, онлайн-PvP, реальные соперники, лиги, мировой рейтинг, проверка результатов сервером и другие упражнения ещё не реализованы. Локальный результат можно изменить через инструменты разработчика: он **не является подтверждением честного PvP**.

## Quality gates

Сборка и unit-тесты удостоверяют корректность кода, **но не доказывают** точность подсчёта на всех людях. До реального выпуска нужно проверить счётчик на разных ростах/телосложениях и смартфонах, в том числе частичные приседания, нестабильное освещение и выход из кадра.

## Почему не засчитывается приседание?

Во время тренировки в нижней части видеокадра видна диагностика: **КОЛЕНО (°)**, **ПРИСЕСТЬ (≤ целевой угол)**, затем **ВСТАТЬ (≥ угол возврата)**. Показания относятся к **проекции** угла колена в камере, а не к медицинской или тренерской оценке качества приседа.

- **КАЛИБРОВКА**: встаньте боком к телефону, выпрямитесь и постойте неподвижно. Счётчик запоминает измеренный угол прямой стойки; при слишком малом угле отодвиньте камеру и поправьте ракурс.
- **КОЛЕНО — / ЧЕЛОВЕК НЕ НАЙДЕН**: разместите целиком таз, колени и обе стопы в кадре, добавьте света.
- **СУСТАВЫ НЕ ВИДНЫ**: поменяйте расстояние и боковой ракурс так, чтобы колено не перекрывалось рукой или другой ногой.
- **ОПУСКАЙСЯ / ПРИСЕСТЬ ≤ …°**: счётчик видит ногу, но минимальный угол не достиг проверяемого порога. Не приседайте глубже комфортной амплитуды только ради приложения: измените ракурс или сообщите измеренные значения.
- **ВЫПРЯМИСЬ / ВСТАТЬ ≥ …°**: глубина достигнута; нужно вернуться в исходную стойку, после чего повтор засчитается.
- **НУЛЕВОЙ СЧЁТ ПРИ ПРАВИЛЬНОЙ СЪЁМКЕ**: сообщите значения «КОЛЕНО», «ПРИСЕСТЬ», «ВСТАТЬ» и модель устройства. Видео присылать не обязательно.

## Проверка на реальной камере — ещё не пройдена

После автоматических тестов необходимо провести полевые испытания. Для каждого теста запишите устройство, браузер, освещение, ракурс, ожидаемый счёт и фактический счёт. Видео записывать и отправлять не требуется.

1. **20 полных приседаний:** ровно 20 засчитанных повторений, автоматическая остановка камеры и ровно одна награда.
2. **5 неполных приседаний:** ни одного ложного зачёта (реальная глубина по видео пока не валидирована).
3. **Потеря кадра:** во время приседания уйдите из кадра минимум на 1 секунду и вернитесь стоя. Незавершённое повторение не должно засчитаться; уже выполненные сохраняются.
4. **Отключение камеры:** выключите камеру во время испытания. Приложение должно показать ошибку и не начислять награду.
5. **Два ракурса / два освещения:** сравните счёт с подсчётом человека; зафиксируйте расхождения и условия.

**Не считать PASS по реальной точности**, пока тесты не проведены на людях. Датчик измеряет проекцию коленного угла, но не подтверждает безопасность техники упражнения.

## Если камера не работает

Проверьте разрешение камеры, отсутствие блокировки другим приложением, HTTPS/localhost и доступ к CDN модели. Для ПК лучше использовать боковой ракурс на расстоянии, позволяющем видеть ноги целиком.

### Подсказки по кадру после теста на телефоне (19.10.2026)

Тест с реальным человеком показал кратковременную потерю суставов во время приседаний, особенно при съёмке **спереди**. На мобильном экране добавлен справочный блок **до запуска камеры** и контекстные сообщения в видеопотоке: «не видны колени», «не видны лодыжки», «стопы у края кадра» и «угол не определяется». Краткие ошибки обнаружения подавляются примерно на 0,4 секунды, чтобы подсказка не мигала на каждом кадре.

Рекомендация: поставить телефон вертикально **сбоку от себя**, отойти так, чтобы была видна хотя бы одна полная нога от таза до лодыжки, убрать препятствия и не приседать у края рамки. Подсказки лишь помогают поставить камеру и **не меняют критерия зачёта**: неполное движение не должно давать XP. Для дальнейшего повышения точности нужен тест на телефоне с записанными измерениями MediaPipe, а не только скринкаст интерфейса; сам видеопоток приложением не сохраняется.
