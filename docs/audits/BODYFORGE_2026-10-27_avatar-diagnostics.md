## B. SIFT — воспроизведение

Причина в `Avatar3D.tsx`: `recordAvatarFrame` вызывался только из `animate`, после вызова `redraw`, даже если тот не рисовал. Загрузка модели, ResizeObserver, ручной поворот и изменение тела рисуют через `redraw` без RAF. Поэтому при reduced motion настоящее изменение WebGL не увеличивало счётчик, а GPU counters могли оставаться пустыми. Остановка цикла не очищала старую частоту до следующего кадра; короткая пауза могла попасть в окно измерения.

[FACT] Сначала расширен настоящий `qa:avatar`: WebGL draw calls увеличились после ручного изменения телосложения, а `snapshot().avatar.frames` не изменился. Команда завершилась **exit 12**, после 8 успешных предшествующих проверок, с `FAIL diagnostics count real manual renders with reduced motion`; uncaught browser errors `[]`. Полный before-log сохранён локально.

[INTERP] Оценивать оптимизацию по этим данным было бы ненадёжно. Исправление измерений нужно раньше, чем делать выводы о приросте FPS на Android. Предмет текущей итерации — правильность счётчиков; ускорение GPU не заявляется.

## C. Frame

Контракт:

1. `frames` — число завершившихся вызовов `renderer.render` последней сцены; ручные обновления включаются. Не число физических кадров дисплея.
2. GPU counters берутся после этого вызова; это счётчики Three.js, не объём GPU-памяти в байтах.
3. `active` означает, что сцена прикреплена; добавлен независимый `animating` для разрешённого непрерывного цикла.
4. `observedFps` вычисляется только при работающем цикле и достаточном числе интервалов. На паузе/unmount — `null`; после возврата окно собирается заново. Повторная синхронизация без смены состояния окно не очищает.
5. Неудавшаяся/заблокированная попытка рисовать не добавляет кадр. Камерные метрики, сохранения и награды не меняются.

`schema=bodyforge.runtime-diagnostics.v1` сохранена; новое boolean-поле `avatar.animating` добавлено совместимо с имеющимися читателями приложения. Данные остаются в RAM вкладки; в storage, память Искры или сеть они не отправляются. Копирование JSON по-прежнему требует явного действия пользователя.
