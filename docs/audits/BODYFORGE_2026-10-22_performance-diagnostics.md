# BODYFORGE · Диагностика производительности v1
Дата: 2026-10-22. Слой: приложение, без изменения игровой экономики или канона Искры.
База перед этой итерацией: `664d18b9f3a98f85b6fc716a9a1db72fb0b8adac` (main, clean).

## Цель
Перестать угадывать производительность на телефоне. Замерять без вмешательства в
правила распознавания упражнений: синхронное время MediaPipe, частоту реально
обработанных кадров, отрисовку Three.js и первое завершённое импортирование GLB.

## Технический контракт
- `src/lib/runtimeDiagnostics.ts`: ограниченные до 120 значений серии (миллисекунды).
- Камера: число обработанных кадров, p50/p95/max времени одного `detectForVideo()`,
  приблизительная частота реально обработанных кадров. p95 = `null` при числе образцов <20.
- 3D: время загрузки и подготовки GLB, приблизительные отрисовки в секунду,
  `renderer.info.render.calls`, `renderer.info.memory.geometries` и `textures`.
  FPS относится к активной 3D-сцене, а не к дисплею или графическому процессору в целом.
- `src/components/RuntimeDiagnosticsPanel.tsx`: закрыт по умолчанию, обновляет UI
  раз в секунду только в открытом состоянии. Экспорт только вручную через кнопку.
- В RAM остаются только числовые показатели. Видеокадры, скелет, лица,
  имена, deviceId, результаты тренировок и данные профиля не записываются.
- Данные не передаются по сети, не попадают в localStorage/IndexedDB,
  не меняют XP и исчезают при закрытии страницы. В браузерном тесте проверяется
  отсутствие полей личных данных в копируемом JSON.
- Показатель p95 нельзя трактовать как измерение FPS: это разные величины.
  Нулевые/невалидные значения и паузы не превращаются в выдуманные оценки.

## Как проверить на физическом смартфоне
1. Открыть приложение по **HTTPS**, желательно на том же телефоне, где тренируются.
   HTTP по Wi-Fi позволяет увидеть интерфейс, но не всегда разрешает камеру.
2. Вкладка «Камера» → «ДИАГНОСТИКА УСТРОЙСТВА» → открыть.
3. Начать тренировку. Дать поработать распознаванию 30–60 секунд, не закрывая
   страницу. Смотреть число обработанных кадров и p95 после 20 образцов.
4. Нажать «СКОПИРОВАТЬ ПОКАЗАТЕЛИ» и сохранить только JSON с числами.
   Видео не загружать. Если копирование недоступно, текст можно выделить вручную.
5. Вернуться к герою, сравнить время появления модели и отрисовки.
   Повторить после нескольких переходов «Герой ↔ Камера». При сильном нагреве
   или задержках прекратить тест.

## Обязательные проверки до слияния
- `npm test` (включая границы памяти/замеров).
- `npm run build` (TypeScript + Vite).
- `npm run qa:avatar`: поворот с клавиатуры без RAF в reduced-motion,
  фоновая вкладка не делает GPU draw calls, восстановление после unmount.
- `npm run qa:mobile`: экран 360/390px, GLB load, диагностика
  камеры, переходы объективов, камера без наград за отмену.
- `npm run qa:tower20`, `npm run qa:privacy`,
  `npm run qa:resilience`: экономика, приватность, устойчивость.

## Незавершённые ограничения
- Точность настоящих приседаний и FPS на Android пока неизвестны.
- Первый вызов MediaPipe может быть существенно тяжелее следующих; измерять
  достаточно долгую сессию. Грубый p95 менее чем по 20 кадрам не выводить.
- Web Worker пока не внедрён: нужны реальные измерения, совместимость
  передачи кадров, тест отсутствия повторных наград и сохранение fallback.
- Не выводить паспорт устройства или видео в отчёт; никакой фоновой телеметрии.
- Изменения параллельной сессии в game/progression/rewardIntegrity не входят
  в этот ограниченный performance-дифф и должны пройти независимую проверку.

## Rollback
Откатить только изменения модуля диагностики, панели и точечных вызовов в App /
Avatar3D; не выполнять `git reset --hard` или `git clean -fd` на общем
рабочем дереве. Сохранения пользователя и правила XP не трогать.
