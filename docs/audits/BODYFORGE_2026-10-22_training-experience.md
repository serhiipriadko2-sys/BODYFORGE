# BODYFORGE: тренировочный опыт v0.4 — интерфейс и границы

Дата проекта: 2026-10-22
Исходная ветка: main / f23a8b8b1b1ddb856c49b13a4aae276544078fcd
Рабочая ветка: feat/guided-training-and-daily-plan-20261022
Область: новый пользовательский опыт BODYFORGE, без изменения ядра Искры и правил выплаты наград.

## Цель и референсы

Референсы GymScape на телефоне содержат:
1. предложение подключить шаги с устройства / Health Connect;
2. связку упражнений с RPG-ресурсами и атаками;
3. инструкцию постановки телефона, демо упражнения;
4. редактируемый ежедневный список и цели;
5. справочник камеры по разным упражнениям.

Адаптация не копирует художественные ассеты, ролики, тексты, логотипы,
название игры, сторонние IP и предполагаемые серверные возможности.
BODYFORGE оставляет оригинальный индустриальный стиль с золотой ковкой,
свою башню, персонажа, внутриигровой кошелёк и слежение за приседаниями.

## Что реально реализовано (web v0.4)

- Каталог восьми упражнений и отдельная пошаговая подсказка по камере
  для каждого типа: приседания, выпады, отжимания, прыжки с разведением,
  высокие колени, подъёмы корпуса и ног, планка.
- ТОЛЬКО приседания имеют автоматическое распознавание и награды.
  Неподдерживаемые упражнения могут открывать гид, но не запускать
  подсчёт или выдавать XP. Камера, если пользователь выбрал гид,
  предлагает сперва вернуться к поддерживаемым приседаниям.
- Видимая на главной дневная цель 20—200, с шагом 20.
  Это соответствует текущему фиксированному подходу камеры (20).
  Число выполняется только по реально завершённым и сохранённым
  тренировкам из профиля; начало, отмена, неуспешное сохранение
  или ручной ввод не учитываются.
- Цель — UI-настройка без дополнительной выплаты; сохраняется отдельно
  в локальном хранилище браузера с read-back. При недоступности
  памяти показывается ошибка, сохранение не заявляется.
- Ручная запись шагов только за текущий день с явным source=manual,
  диапазон 0—100000, защита неверных/повреждённых данных, read-back.
  Это НЕ авточтение шагов, НЕ шагомер, НЕ внутриигровой ресурс и НЕ XP.
- В карточке пути игрока явно написано, что Health Connect не подключён,
  что запись на одном браузере не синхронизируется на другие устройства.
- Обновлены responsive стили для 360/390px, без горизонтального скролла.
- Рисунок постановки телефона создан средствами интерфейса (CSS/иконки),
  без сторонних роликов, копированных кадров и изображений.

## Данные и контракты

Дневная цель: bodyforge:daily-plan:v1, JSON version=1, targetReps=20..200
с кратностью 20. Граница хранения — текущий origin браузера.

Ручные шаги: bodyforge:manual-steps:v1, JSON version=1, day=<local yyyy-mm-dd>,
count=0..100000, source=manual. Предыдущий день не переносится, история
пока не ведётся, никакого соединения с сервером.

Прогресс тренировок продолжает храниться строго под
bodyforge:pilot:v1 и через существующий lock+journal и антидубль.
Новая работа НЕ меняет формат профиля и НЕ создаёт обход этого контура.
Новые настройки не превращаются в подтверждённый игровой прогресс.

## Тесты и приёмка

- TypeScript + Vite сборка;
- все Vitest тесты, включая повреждённый JSON, переполнение, смену дня,
  недоступность localStorage, подсчёт только сохранённых повторений;
- отдельный браузерный QA тренировки: 25 проверок, размер 360/390 px,
  выживание предпочтений после reload, отсутствие XP от ручных шагов,
  гайд отжиманий без ложного запуска;
- старый мобильный E2E, синтетические 20 приседаний, добавочная проверка
  100% дневной цели только после сохранения победы;
- private paths, 3D lifecycle, camera-runtime, journal/finish-save/multitab.
- внешний мобильный HTTPS деплой только после независимого gate.

## Следующие шаги — не выдавать за готовые

**Этап 2 — новые распознаватели.** Отдельный интерфейс ExerciseDetector:
kind/id, cameraOrientation, initialize/reset/process, detected cycle,
confidence, lost-frame handling и тесты на реальные движения с согласованной
методикой. Изолированная оценка recall и false positives на разных позах;
никаких XP до прохождения приёмки на реальном Android. Видео для обучения
создать самостоятельно или использовать только лицензированное.

**Этап 3 — Android Health Connect.** Нужен Android native bridge с
ограниченным разрешением READ_STEPS, экраном согласия, режимами
unavailable / denied / connected / revoked, чтением агрегированных
StepsRecord.COUNT_TOTAL за локальный день, корректным учётом часового пояса,
пересечений источников и отзывов доступа. Отказ в разрешении не блокирует
тренировки. Не запрашивать запись шагов или другие медицинские категории.
Синхронизированные шаги нельзя смешивать с ручными без явного provenance;
задвоения разных устройств и повторного чтения недопустимы.

**Этап 4 — RPG за шаги.** Отдельная антифрод-экономика, лимиты, idempotent
transaction IDs, серверная проверка перед PvP. Ручные оценки должны
оставаться НЕплатёжными. Только после отдельно утверждённых правил
можно менять ресурсный и боевой баланс.

## Обнаруженные дефекты и исправления в QA этой итерации

- В исходной main@f23a8b8 многовкладочный E2E воспроизводимо зависал
  на «ОТКРЫТЬ АКТУАЛЬНОЕ СОХРАНЕНИЕ» при удержании блокировки другой вкладкой:
  чистое чтение ошибочно требовало исключительной блокировки записи.
  Минимальное исправление в `useProfileStorage` выполняет предварительный
  read-only контроль ОБОИХ журналов: localStorage и IndexedDB. При пустых
  и доступных журналах показывает сохранённое состояние без write lock;
  если есть хоть одна запись либо ошибка доступа — выполняет исходный
  защищённый replay. Отзыв разрешений, конфликт ревизий и pending-result
  по-прежнему fail-closed. Старые профили не мигрируют.
- Проверка покупки мышц в QA была несовместима с фактическим контрактом
  `busy={isSaving}`: пока начисление бонуса не подтверждено записью,
  кнопка покупки намеренно недоступна. Исправленный E2E проверяет
  запрет покупки при pending и разрешение только после durable read-back.
- Эталонный QA журнала повторно использовал test profileId между независимыми
  сценариями, но очищал только localStorage. IndexedDB сохранял settled
  workout по тому же ID и корректно восстанавливал запись, сдвигая этаж.
  В изолированном Chrome QA проверенно удаляет **только свою** БД
  между тестовыми фазами, но не перед эмулированным crash/reload.
- Наблюдение: в одном запуске headless Chrome две вкладки увидели разные
  версии localStorage непосредственно после смены holder Web Lock. Это
  ограничение локальной координации, а не доказательство защиты от
  мошенничества/гонок между устройствами. Прямое соревнование за реальные
  награды в общем онлайн-кошельке нельзя включать до серверного idempotent
  ledger с атомарным сравнением версий. Не объявлять proof of correctness
  по одной зелёной итерации многовкладочного теста.

## Rollback и непритязания

Вернуть только feature-коммит. Не использовать git reset --hard на общей main.
Миграция существующих профилей НЕ нужна: старый ключ/сохранения не меняются.
Невозможно утверждать, что Health Connect, ролики, все движения, APK, онлайн
или телефонная точность работают, пока не появятся соответствующие код,
разрешения, физическая QA и разрешённые публикации.
