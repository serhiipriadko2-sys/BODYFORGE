# BODYFORGE · загрузка камеры по требованию
Дата: 2026-10-22. Рабочая ветка: feat/on-demand-pose-runtime-20261022.
Основа: main@664d18b9f3a98f85b6fc716a9a1db72fb0b8adac.
**Статус:** проверка изменения в отдельной ветке; production rollout и Android не заявляются.

## Почему
В исходной сборке задача распознавания позы импортировалась статически из
`src/App.tsx`. Даже пользователь, который только настраивал бойца,
загружал и разбирал JavaScript MediaPipe, не открывая камеру.

## Контракт решения
- TypeScript тип `PoseLandmarker` импортируется через `import type`; runtime-код не
  попадает в первоначальный JavaScript chunk.
- Runtime `@mediapipe/tasks-vision` запрашивается только после
  явного старта тренировки и успешного получения потока камеры.
- Импорт ограничен 20 секундами; при ошибке исходный видеопоток закрывается.
- Ошибка JavaScript chunk не превращается в повторное автоматическое
  открытие камеры. Пользователь видит отдельную кнопку обновления страницы:
  старые браузеры могут кешировать failed dynamic import до перезагрузки.
- Токен поколения `requestId` не позволяет поздно загрузившемуся
  модулю возобновить уже отменённый запуск.
- CPU/GPU выбор MediaPipe, работа тренировок и правила XP не меняются.
- Worker/GPU offloading не заявлены; detectForVideo остаётся синхронным.

**Не равняется подтверждённому ускорению в секундах:** Vite размер бандла не
измеряет время реакции телефона. После нажатия Start динамический chunk всё
равно должен быть загружен; холодный запуск камеры может немного замедлиться.
Модель и WASM в текущей конфигурации по-прежнему загружаются из публичных
CDN/Google endpoints и требуют подключения при первом обращении.

## Контроль и безопасность
- `npm test` и `npm run build`.
- `npm run qa:bundle`: проверяет реально собранную структуру chunk и
  не допускает незаметного возврата MediaPipe в основной JS.
- `npm run qa:camera-runtime` на Vite localhost: контроль отсутствия
  загрузки до нажатия камеры, блокировки JS-запроса, закрытия fake tracks,
  сообщения об ошибке, восстановления после reload, отмены при задержанном
  ответе импорта и запрета позднего возобновления.
- Регрессии `npm run qa:mobile`, `npm run qa:tower20`,
  `npm run qa:resilience`, `npm run qa:privacy` и `npm run qa:avatar`.
- Никогда не подменять результаты синтетической камеры измерениями живого человека.

## Риски и дополнительные действия
- Для оценки реального выигрыша нужны Chrome DevTools / Android traces
  cold/warm start на смартфоне.
- Динамический import не работает без доступного JS-ресурса: откат — revert
  отдельного commit; UI остаётся работоспособным без камеры.
- Долгая синхронная инференция после запуска пока не решена. Для Worker нужны
  самостоятельные испытания, измерения и новые тесты отсутствия двойных наград.
- Основная ветка и незавершённые изменения других сессий не изменяются.
