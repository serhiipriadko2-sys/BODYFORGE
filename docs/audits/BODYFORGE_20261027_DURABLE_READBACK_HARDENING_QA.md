## A–B. Наблюдения до исправления

Профильная регрессия трёх модулей сначала: **24 PASS / 11 FAIL** (35 тестов). Десять ошибок были связаны с устаревшими заглушками `markDurableResults`, которые возвращали лишь `{status:'saved'}`, хотя новый IndexedDB-контракт требует `{status:'saved', entries:[...readback]}`. Один старый тест считал готовым идентифицированный профиль с оплаченными тренировками и отсутствующим журналом идентификаторов — это противоречит защите от повторной выплаты.

После приведения тестов к действующему контракту был найден **новый реальный дефект на границе доверия**: неполный ответ «saved» с пустым `entries` признавался успехом, а ответ без `entries` выбрасывал `TypeError`. Новые тесты воспроизвели оба случая как RED до исправления.

## C–D. Внесённые изменения: точный scope

1. `src/lib/durableWorkout.test.ts` — тестовый IndexedDB-записыватель теперь имитирует чтение записей после коммита, а не выдаёт один оптимистический статус. Добавлены проверки отсутствующего, пустого и неподтверждённого ответа; проверка безопасного повторного подтверждения *без двойного XP*; запрет удаления локального оригинала при недоказанной карантинной записи.
2. `src/lib/dedupRecovery.test.ts` — тестовые `stage`/`mark` возвращают записи по новому контракту. Идентифицированный профиль со старыми оплачиваемыми тренировками, но без журнала ID, остаётся `recovery-required`: исходный профиль и баланс сохраняются, новая награда запрещена до доверенного восстановления. Анонимный legacy-профиль без такого журнала остаётся читаемым, без выдуманных ID.
3. `src/lib/durableWorkout.ts` — функция `verifiedTerminalRows` сверяет **точное число**, неизменяемые ключи/содержимое, отсутствие дубликатов и терминальное состояние каждой записи, подтверждённой IndexedDB. Без полного read-back окончательная отметка о погашении не выдаётся; при карантине исходная локальная копия не удаляется. При ошибке после уже применённого локального результата активная durable-запись сохраняется для повторной обработки; повторная обработка не должна платить ещё раз.
4. `qa/stable-dev-server.mjs` — новый отдельный Vite-сервер только на `127.0.0.1`, по умолчанию порт 5174, с `hmr:false` и `strictPort:true`, чтобы редактирование приложения не перезагружало вкладки во время выполнения camera/lock E2E. Источники **не заморожены** между явными навигациями: это не эквивалент статической production-сборки.
5. `package.json` — `npm run qa:serve-stable`.
6. `README.md` — команды для двух терминалов PowerShell и границы тестового сервера. Обычный `npm run dev` не меняется.
